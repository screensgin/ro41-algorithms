# СРС 8. Трассировка методов string и StringBuilder

## 1. Трассировка Trim() и Split(';')
Исходная строка: `s = "  Ахметов Ерлан;85 "`

1. **Метод `s.Trim()`**: Удаляет пробелы в начале и в конце строки.  
   Результат: `"Ахметов Ерлан;85"`
2. **Метод `.Split(';')`**: Разбивает строку на массив строк по разделителю `;`.
   * **Элемент 0:** `"Ахметов Ерлан"`, длина = `13` символов (включая пробел между фамилией и именем).
   * **Элемент 1:** `"85"`, длина = `2` символа.

## 2. Трассировка int.TryParse для line = "Иванов Пётр;70;85;x"
После разделения строки `line.Split(';')` получаем массив из 4 элементов:

| Индекс | Часть строки | Результат `int.TryParse` | Значение `out` |
| :--- | :--- | :--- | :--- |
| `0` | `"Иванов Пётр"` | `false` | `0` |
| `1` | `"70"` | `true` | `70` |
| `2` | `"85"` | `true` | `85` |
| `3` | `"x"` | `false` | `0` |

* **Что вернёт метод проверки оценок (например, `TryParseScores`) и почему?**  
  Метод вернёт `false`, так как в массиве присутствуют элементы (`"Иванов Пётр"` и `"x"`), которые невозможно корректно преобразовать в целое число с помощью `int.TryParse`. Для успешного завершения проверки все числовые поля должны успешно парситься.

## 3. Сравнение создания объектов: string против StringBuilder

### А) Конкатенация строк `string s = ""; for (i = 0; i < 4; i++) s += i;`
Строки в C# **неизменяемы (immutable)**. Каждая операция `+=` не изменяет существующую строку, а создаёт **новый объект** в памяти.

| Шаг / Итерация | Действие | Созданные объекты `string` |
| :--- | :--- | :--- |
| Инициализация | `string s = ""` | Объект 1: `""` |
| Итерация 0 ($i = 0$) | `s += 0` | Объект 2: `"0"` |
| Итерация 1 ($i = 1$) | `s += 1` | Объект 3: `"01"` |
| Итерация 2 ($i = 2$) | `s += 2` | Объект 4: `"012"` |
| Итерация 3 ($i = 3$) | `s += 3` | Объект 5: `"0123"` |

* **Итог для `string`:** Создаётся **5 объектов** (1 начальный + 4 в процессе цикла).

### Б) Использование `StringBuilder` (`sb.Append(i)`)
`StringBuilder` работает на основе внутреннего изменяемого буфера (`char[]`). При добавлении данных новый объект в памяти не создаётся (буфер может лишь динамически увеличиваться при переполнении).
* **Итог для `StringBuilder`:** Создаётся всего **1 объект** самого класса `StringBuilder`.

## 4. Объяснение поведения s.ToUpper() без присваивания
* **Почему строка не изменилась?**  
  В C# тип `string` является неизменяемым (`immutable`). Все методы класса `string` (включая `ToUpper()`, `Trim()`, `Replace()`) не меняют исходный объект в памяти — они генерируют и возвращают **новую** строку с внесенными изменениями.
* Если не сохранить результат выполнения метода обратно в переменную (`s = s.ToUpper();`), то ссылка на новый объект потеряется сборщиком мусора, а переменная `s` продолжит указывать на старый исходный объект в нижнем регистре.
